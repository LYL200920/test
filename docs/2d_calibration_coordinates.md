# 2D 标定第一阶段：坐标与归档契约

## 范围

本阶段提供独立的数据结构、严格验证、归档读写和变换组合，不接入运动、UI 或拼图运行路径。不更改旧相机内参 XML、Tool、Progress 或 RT_eyetohand.txt。

现场结构：固定 3D 相机为眼在手外；末端 2D 相机为眼在手上。两台相机之间不存在与机器人运动无关的固定变换。

## 坐标约定

`T_A_B` / `A_from_B` 将 B 中的列向量转换到 A：`p_A = T_A_B * p_B`。

- R：由 `reference_frame_id` 明确命名的机器人参考坐标，不默认等于 WORLD 或某个 BASE。
- F：法兰，不能直接用非零 TOOL 下的 TCP 位姿替代。
- C：2D 光学坐标，X 向右、Y 向下、Z 向前。`Intrinsic_Profile` 仅使用 OpenCV 针孔 Brown-5 模型；已确认的远心镜头不能套用该模型，见下文独立分支。
- P：右手工作平面坐标，Z=0 是平面，X/Y 定义拼图方向，Z 为法向。
- 长度 mm；关节角和 XYZABC 角度 degree。复用项目 `Build_Zyx_Pose_Matrix`，旋转为 Rz(A) Ry(B) Rx(C)。归档中的位姿以 4×4 矩阵保存，不存具有歧义的裸 XYZABC。
- 矩阵必须有限、旋转正交、det(R)=+1、齐次末行=[0,0,0,1]。

核心关系：

```
T_R_C2(i) = T_R_F(i) * T_F_C2
T_R_B(i) = T_R_F(i) * T_F_C2 * T_C2_B(i)
```

固定标定板应使第二式跨姿态一致。已有 3D 外参只有在它的目标参考坐标与 R 一致时才能直接使用；否则必须显式串接参考坐标变换。

当前 KRL 状态来自 `$POS_ACT`，应用默认笛卡尔命令 BASE/TOOL 为 0。部署端实际 BASE/TOOL、WORLD/机器人参考含义、外轴情况仍须现场确认。本阶段不自动解释或转换控制器状态，也不把编号相同视为物理参考已经验证。

## 数据对象

`calibration_geometry.h` 定义：

- `Intrinsic_Profile`：复用 K/D 和棋盘结果，增加标定ID、创建UTC文本、相机/镜头配置与ROI/binning。
- `Hand_Eye_Profile`：明确 `flange_from_camera`，关联内参版本、机器人参考、求解方法、训练/独立验证样本数和三类误差。
- `Work_Plane_Profile`：明确 `reference_from_plane`、有限平面区域、来源与源标定版本。3D来源指固定相机的眼在手外标定版本。平面原点/XY方向不能仅凭法向确定。
- `Hand_Eye_Sample`：图片相对路径、会话/样本/点/标定板身份、实际法兰矩阵与关节、运动/状态请求编号、状态revision、上报BASE/TOOL、主机时序、相机帧号、可选设备时钟、角点、状态和拒绝原因。

图像配置的ROI以binning前传感器像素计，输出尺寸必须等于ROI尺寸除以binning。不建模额外decimation/软件裁剪；第二阶段需读取实际SDK节点并转换到此约定，未知配置不得猜成全幅。`lens_configuration_id` 表示用户确认不变的焦距/焦点/光圈配置，不意味着当前可自动读取这些物理参数。

光学外参与名义工作距离上的虚拟视觉TCP分开；不得自动将手眼结果写入机器人Tool或改变既有示教点。

## 匹配与验证

`Validate_Calibration_Archive` 检查结构与引用一致性，不证明标定精度。手眼结果要求至少3个训练样本和1个验证样本作为结构下限；这不是推荐采样数量，也不是姿态充分性的判定。

`Match_Calibration_Context` 是未来标定拼图的严格入口：必须同时具备内参、手眼、平面，且相机序列号、镜头配置、尺寸、ROI、binning、内参版本、机器人型号与参考标识匹配。不自动回退旧拼图模式。残差是否满足业务容差、标定版本是否仍有效，需要后续应用层判定。

样本集合限制为同一会话、同一固定且方向一致的标定板与机器人参考。采集尚未求出手眼时可只包含内参和样本。Accepted样本必须有已核验位姿标记及完整、界内角点；Rejected必须有原因。完全缺失位姿的失败尝试应记录为采集日志，而不是伪造矩阵补成标定样本。

主机时间是会话内steady-clock纳秒；设备时间是带时钟身份和tick周期的原始计数，二者没有默认同步关系。主机时序字段支持审计，不等于曝光同步证明。`pose_verified` 必须由第三阶段采集流程验证命令归属、状态新鲜度与停稳后设置，不能由文件加载器推断。

## 持久化

新格式根为 `CalibrationArchive`，version=1，显式写入单位、矩阵方向、相机轴和法兰位姿约定。旧格式不隐式迁移，也不修改旧文件。

- 保存前验证，拒绝覆盖任何已有目标；调用者应提供唯一文件名和已存在的父目录。
- 独占创建同级 `.staging` 目录，完整写入后通过同卷硬链接发布；目标已存在则失败。文件系统必须支持硬链接（如本机NTFS），不支持时明确失败，不降级为覆盖写入。不是断电持久性保证。
- 加载上限32 MiB，严格检查必填字段、重复/未知节点、枚举、完整数值、有限性、版本和约定。失败保持调用者原输出不变。
- 图像路径使用UTF-8归档相对路径，禁止绝对路径、盘符和 `..`；加载不打开图像、不执行路径、也不确认图像内容。
- 创建UTC字段当前是必填来源标签，不承担日期运算/时钟校准。结构验证不是签名或来源可信性认证。

## 后续接线顺序

以下为针孔模型路线。远心镜头不直接使用标准针孔 solvePnP + calibrateHandEye；后续需要机器人平移—图像位移约束、3D工作平面/机械参考和远心模型的联合求解。理想远心投影不能单独确定光轴方向的原点，150 mm工作距离不等于Tool Z或焦距。

1. 内参配置管理、SDK成像设置匹配及去畸变预览。
2. 手眼成对采集、实际法兰转换/新鲜度验证、离线会话重放。
3. 手眼求解、姿态退化检查和独立验证，生成 `Hand_Eye_Profile`。
4. 标定板/固定3D相机工作平面测量。
5. 新的标定投影拼图模式，与旧Tool+FOV模式并存。
6. 静态停拍验收后再接飞拍时序。

## 测试

`calibration_geometry_tests` 使用运行时 Require，不依赖发布配置下失效的 assert。覆盖变换方向/角度约定/逆变换、无效刚体矩阵、设备/ROI/版本/参考不匹配、样本状态与时序、UTF-8和64位帧号、归档全字段往返、不覆盖、畸形XML及失败输出不变。

## 棋盘检测：粗定位与原分辨率重检测

- 全图最长边限制为2048像素做SB/传统检测粗定位。坐标恢复使用实际缩放后尺寸及像素中心约定。
- 用粗定位包围框，加至少24像素且约两格间距的边界，在原灰度图ROI内优先SB重检测，失败或几何检查不通过时尝试ROI传统检测；最后才尝试原粗定位的亚像素结果。每条路径都必须通过相同质量检查。
- 亚像素处理后检查完整角点数、有限值/边界、相邻网格局部连续性及四边形方向/拓扑。局部二阶差分门槛为相邻平均间距的24%，短边下限2像素；这是粗错误筛查，不是亚像素精度验收，极端透视或严重畸变也可能被拒绝。无需假定针孔图片是仿射平面。
- 不用拟合网格替代实测角点，不自动删除个别角点。无法得到完整且一致的网格时按“未检出”处理，不加入求解；诊断保留疑似角点邻域的零基行列索引。
- 采图列表新增检测诊断列，双击可查看完整重试路径；开始计算时也复制到计算日志。检测方法和诊断是本次采集结果元信息，不属于标定参数。
- `chessboard_detection_tests` 覆盖透视网格、反向编号、局部异常、交叉/重复角点、真实合成图检测、非整数缩放坐标恢复及空白图。可另传图片目录运行离线远心回归，不写标定文件。

## 远心分支：固定平面位移映射

准备页选择“远心镜头（固定平面位移映射）”。复用棋盘检测、导入/采图、样本移除、覆盖审查和后台进度日志，不调用针孔内参求解器。

- 固定标定板、工作高度及相对姿态，仅做平面内平移。至少10张有效图，棋盘中心覆盖九宫格中至少5区；建议覆盖中心、四边、四角。数量/覆盖门槛不能证明畸变或精度满足要求。
- 旧针孔采图Progress中的倾斜点不适用于本模式。选择远心模式不会修改、过滤或重写机器人Progress；操作前必须人工确认轨迹。本版本不验证实际曝光位姿。
- 模型为 `[du,dv] = A * [dX,dY]`，A为共享2×2矩阵，单位px/mm，各图独立移除平移。输出逆矩阵用于像素**位移**转棋盘平面毫米位移，而非绝对像素坐标转机器人位置。
- 正反角点顺序通过相对首张图的180°翻转归一化。无法确定带物理标记的绝对棋盘原点/轴，也不能区分真实180°旋转与检测顺序翻转。
- 对每图计算共享模型下RMS、最大角点残差及相对共享矩阵的Frobenius范数偏差百分比。默认分别要求≤0.75px、≤2px、≤1%；失败保留样本和报告，不自动删除倾斜或异常图，不将失败输出写入结果。
- 结果页显示矩阵和逐图诊断。残差是训练数据一致性指标，**不是独立测量精度**。另取未参与拟合的已知长度/位移，并在目标工作区域验证；超差应改善角点、目标平整度或进一步建模畸变，不宜直接放宽阈值。
- 独立远心配置绑定来源相机/ROI/binning/镜头配置及固定工况ID（平面、工作高度、相对姿态）。新版本保存为`Config/CameraCalibration/telecentric-plane-<时间编号>.xml`，不覆盖旧文件，不伪造K/D，不与针孔归档互读。加载不会全局启用。
- **未实现非线性畸变校正、光轴深度/绝对原点、法兰外参和拼图接入**。因此远心版本管理不提供针孔去畸变预览，不改写Tool、示教点或原始图片。改变工况后必须重新验证/标定。
- 核心API结构下限为3张；面向操作人员的向导采用更严格的10张和5区门槛。API调用方仍负责样本覆盖、物理工况及独立验证。

## 远心平移会话：第一步仅采集审计，尚不可求解

准备页“建立远心平移采集会话（实际状态审计）”加载一个已保存的远心版本，填写参考来源标签及固定板ID，人工确认光学/工况一致。初始化只建目录，不启动机器人。继续使用采图页的Progress检查和独立运动确认；不修改轨迹、Tool或旧拼图。此模式禁用手动最新帧、离线导入和删样本，以免制造无来源配对。

- 保存位置：当前Resource下`Config/CameraCalibration/TranslationSessions/translation-<编号>/`，含`images/`和不可覆盖的`session-<编号>.xml`检查点。开始运动前写空会话，每张图检测后另存完整检查点；写入失败停止后续流程，已写原图保留。检查点位于同一目录，图片路径始终相对该目录。
- 每样本保留点位/重试/运动序号、图像帧号、角点与检测诊断，以及触发前和观察到新帧时的最近机器人反馈。反馈带接收回调时刻、revision、原始request_sequence、运动状态、关节、原始XYZABC及上报BASE/TOOL。不填入目标位姿冒充反馈。按Progress零基索引每4点预留1点为validation；重试沿用角色，仅为预分组，不代表独立验证已经完成。
- `frameObservedNs`是UI轮询看到帧的时刻，不是SDK收帧或曝光时刻。`capturedUtc`是样本记录创建的UTC标签。机器人时间是状态回调到达主机的steady-clock纳秒；不与机器人/相机设备时钟默认同步。当前前后快照可能是同一个缓存状态，`matchedStateRequest=false`明确表示尚未发起、匹配专用采样请求。
- 归档根为`TelecentricTranslationSession`，purpose固定为`acquisition-only-unverified`，原始笛卡尔反馈不得解释为已验证的法兰外参。允许保存缺失/陈旧状态用于诊断，但加载不会提升其可信度；不提供映射求解或拼图启用。
- `Check_Translation_Capture_Timing`仅用于未来采样器的主机时序门槛：两个明确关联请求的IDLE响应、更新revision、250ms新鲜度和前后时序、已知且不变的BASE/TOOL。通过也不证明物理坐标、姿态稳定或曝光同步；当前缓存采集不会通过此门槛。
- 后续必须补齐专用GET_STATE前后采样状态机、连接/采图代际与独占触发关联、实际BASE/TOOL转换合同及稳定性检查，再实现运动映射求解。仅有控制器上报编号不足以证明真实激活变换，禁止直接用编号0推断法兰坐标。

## 第二阶段：内参版本与去畸变对照（仅针孔）

入口：2D相机 → 相机内参标定 → 准备页的“内参版本管理 / 去畸变对照”。标定结果页“保存并完成”也打开同一窗口。

- 加载第一阶段的内参归档，或读取旧版内参XML。旧格式缺少ROI/镜头信息，必须确认来源并补全后另存新版本；旧文件不修改。
- 新计算结果不会自动绑定当前连接相机。用户必须填写真实来源，混合相机/光学设置的数据集应丢弃并重新采集，不应仅通过填写元信息将其声明为一致。
- “读取连接相机ROI”通过SDK读取Width/Height/OffsetX/OffsetY。当前适配仅支持无镜像、binning和decimation均为1；不可读取时拒绝猜测ROI。未暴露的binning/decimation节点按设备未提供对应功能处理，现场仍需核验该型号是否存在其它缩放模式。
- 镜头配置ID代表用户手动确认的镜头/对焦/光圈，不是自动测量结果。新归档保存到Config/CameraCalibration/intrinsic-<时间编号>.xml，禁止覆盖历史版本。
- “对照最新帧”检查序列号、尺寸、ROI和配置；不发送触发，也不更改相机。旧模式切换后请先获取新帧。只展示冻结帧，不是实时视频。
- 离线对照能自动检查尺寸，但无法从普通PNG/JPEG证明设备/ROI身份，须人工确认来源。
- 对照计算在后台线程，输出尺寸和K不变，不裁剪；输出对应D=0，边缘可能黑色，原始文件/像素不修改。不要把纠正后图像再按原D处理。
- 配置选择仅在窗口内有效，明确标为“未全局启用”。本阶段没有自动接入实时预览、模板定位、手眼求解或拼图；后续消费端必须通过匹配接口显式使用。
- 内参求解与工作流旧测试的assert已改为运行时Require；新增intrinsic_undistortion_tests包含独立Brown-5合成映射、零畸变、Gray/RGB/BGR与stride、黑边和无效输入测试。测试通过不替代硬件SDK及实际窗口验证。
